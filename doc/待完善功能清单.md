## 一、后端 (AutoMarketing)

### 🔴 高优先级

#### 1. `init_db.py` 的 `task_executions` 表缺少 6 个关键列
- **文件**：`scripts/init_db.py` L140-L156
- **问题**：表定义缺少 `task_name`、`task_config`、`account_id`、`pending_items`、`progress`、`updated_at` 列，但路由和 Worker 中大量使用。通过 `init_db.py` 初始化的数据库在执行任务操作时会报 `no such column` 错误。
- **修复**：在 `init_db.py` 的 `task_executions` 建表语句中补齐缺失列。

#### 2. `task_logs` 表未在建表脚本中定义
- **文件**：`src/worker/runner.py` L57-L62，`src/api/routes/task_executions.py` L375
- **问题**：`task_logs` 表被 Worker 日志写入和任务日志查询接口大量使用，但 `init_db.py` 和 `database.py` 均未定义该表。Worker 尝试写入第一条日志时就会崩溃。
- **修复**：在 `init_db.py` 的 `create_tables()` 中添加 `task_logs` 建表语句。

#### 3. `ai_models` 表列名不匹配：代码用 `api_url`，数据库定义 `base_url`
- **文件**：`src/api/routes/ai_models.py` L47-L87 vs `scripts/init_db.py` L60-L77
- **问题**：`init_db.py` 定义使用 `base_url` 列名，但路由代码 INSERT 使用 `api_url`、SELECT 使用 `row.api_url`。新建数据库会直接报错。
- **修复**：统一列名，建议将 `init_db.py` 中的 `base_url` 改为 `api_url`。

#### 4. `reply` 任务类型在 Worker 调度器中未实现
- **文件**：`src/worker/runner.py` L202-L246
- **问题**：后端提供了 `POST /reply` 创建评论回复任务，但 Worker 的 `_dispatch()` 只处理了 `scrape`、`message`、`reach`，没有 `reply` 分支。任务创建后执行会抛出 `NotImplementedError`。
- **修复**：在 `_dispatch()` 中添加 `reply` 分支，或暂时屏蔽该任务类型的创建入口。

---

### 🟡 中优先级

#### 5. 大量路由文件缺少鉴权
- **文件**：除 `users.py` 和 `roles.py` 外的所有路由文件（共 12 个）
- **问题**：仅用户和角色管理使用了 `Depends(get_current_user)` 鉴权。其余所有 CRUD 接口（包括系统配置、AI 模型管理、任务管理等敏感接口）均无鉴权保护。
- **修复**：在所有需要鉴权的路由处理函数中添加 `current_user: dict = Depends(get_current_user)` 参数。

#### 6. `_count_messages_sent_today` 忽略了 `account_id` 参数
- **文件**：`src/worker/pipelines/tiktok_message.py` L57-L71
- **问题**：函数接收 `account_id` 参数，但 SQL 查询中完全没有使用该参数过滤。多账号场景下风控检查变成全局统计，导致误判。
- **修复**：SQL 中添加 `AND te.account_id = :account_id` 条件。

#### 7. `test_ai_model` 硬编码模型名称
- **文件**：`src/api/routes/ai_models.py` L198-L199
- **问题**：测试 AI 模型连接时，payload 中 `"model": "deepseek-v4-flash"` 是硬编码的，未使用数据库中的 `model_name`。测试非 DeepSeek 模型时会失败。
- **修复**：改为 `"model": row.model_name`，从数据库读取实际模型名。

#### 8. `delete_role` 中冗余的 `fetchone()` 调用
- **文件**：`src/api/routes/roles.py` L191-L194
- **问题**：第一次 `fetchone()` 已消费结果，第二次调用返回 `None`，导致判断逻辑混乱。虽然当前不会误删，但维护风险大。
- **修复**：简化为单次 `fetchone()` + `if not role` 判断。

### 🟢 低优先级

#### 9. JWT 默认密钥硬编码
- **文件**：`src/api/routes/auth.py` L19
- **问题**：`SECRET_KEY` 默认值为 `"automarketing-secret-key-change-in-production"`，开发者容易忽略修改。
- **建议**：启动时若为默认值则打印醒目警告。

#### 10. `create_ai_model` INSERT 缺少必填字段 `model_name`
- **文件**：`src/api/routes/ai_models.py` L85-L87
- **问题**：INSERT 语句只包含 `provider`、`api_key_encrypted`、`api_url`，但表结构中 `model_name` 为 NOT NULL。
- **修复**：在 Schema 和 INSERT 中补充 `model_name` 字段。

## 二、前端 (naive-ui-admin)

### 🔴 高优先级

#### 1. 导出接口 URL 硬编码 `localhost:8000`
- **文件**：`src/api/contacts.ts` L108，`src/api/contents.ts` L75
- **问题**：`getContactExportUrl` 和 `getContentExportUrl` 直接拼接 `http://localhost:8000/api/...` 作为导出链接。生产环境部署后导出功能完全不可用。
- **修复**：使用环境变量中的 API 地址构造 URL。

---

### 🟡 中优先级

#### 2. 生产环境配置未就绪
- **文件**：`.env.production`
- **问题**：`VITE_GLOB_API_URL =`（空值），且 `VITE_USE_MOCK = true`。生产构建中 API 地址为空且 mock 默认开启，部署后所有请求会失败或走入 mock 逻辑。
- **修复**：设置 `VITE_USE_MOCK = false`，`VITE_GLOB_API_URL = /api`。

#### 3. 创建任务页面使用 `setTimeout(300ms)` 等待异步数据
- **文件**：`src/views/tasks/create/index.vue` L440-L448
- **问题**：`onBusinessLineChange` 调用 `loadKeywords` 和 `loadPrompts` 后未 `await`，而是用 `setTimeout(300ms)` 等待。网络慢时数据未加载完，默认值设置失败。
- **修复**：改为 `await Promise.all([loadKeywords(blId), loadPrompts(blId)])`。

#### 4. 应用管理表单缺少必填项校验
- **文件**：`src/views/config/platforms/index.vue` L228-L246
- **问题**：`submitForm` 提交前没有校验 `formData.name` 是否为空，可创建无名应用。
- **修复**：添加 `if (!formData.name)` 校验。

#### 5. AI 模型配置表单缺少必填项校验
- **文件**：`src/views/config/ai-models/index.vue` L251-L277
- **问题**：创建模式下 `provider`、`api_key`、`api_url` 均可为空提交，创建出无效配置。
- **修复**：添加必填项校验。
